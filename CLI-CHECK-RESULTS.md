# Ревью: фича «Слой колодцев на карте»

Сверяю три результата (архитектор, backend, фронтенд) между собой, с рамками проекта и с инвариантами. Ниже — конкретные расхождения.

## 1. Нарушение инварианта «1С — источник истины»: запись бизнес-объектов в gisdata

- **Что не сходится.** В `gisdata/models.py` модель `Well` объявлена как обычная managed-модель GeoDjango с полями бизнес-атрибутов (`external_id`, `object_type`, атрибуты карточки) и с `source` (1С / ГИС). Ничего не мешает Django-коду создавать/обновлять `Well` напрямую через ORM, минуя 1С. Архитектор в разделе «Модель данных» тоже не зафиксировал запрет на прямую запись — только упомянул `external_id` как ключ сопоставления.
- **Чем грозит.** Прямая запись колодца в `gisdata` из Django создаст расхождение с 1С, которое потом нечем разрешить: `external_id` не спасёт, если запись создана без него. Это прямое нарушение инварианта «писать бизнес-объекты напрямую в gisdata, минуя 1С, нельзя».
- **Что должно быть.** Либо модель `Well` — read-only для бизнес-атрибутов (запись только через сервис синхронизации с 1С), либо явно разделены «геометрия/служебные поля, которые правит ГИС» и «бизнес-атрибуты, которые приходят из 1С». В текущем виде этого разделения нет ни в модели, ни в тексте архитектора.
