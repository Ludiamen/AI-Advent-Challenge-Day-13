# Ручная проверка Дня 13 в браузере

Сценарий для проверки руками: убедиться, что состояние задачи формализовано
(этап, шаг, ожидаемое действие), что задачу можно остановить на любом этапе и
что продолжение не переигрывает пройденное и ничего не переспрашивает.

Каждый шаг устроен одинаково: **что сделать** → **что должно получиться**.
Идите по порядку: части 3-6 опираются на задачу, заведённую раньше.

Время: около 35 минут. Вызовов модели: 12-15. В шапке выберите модель
**DeepSeek V4 Flash (ds-flash)** — она платная, но быстрая и не упирается в
минутные лимиты Groq, из-за которых прогон сценария растягивается.

Сценарий пройден в настоящем браузере (headless Chrome) на модели `ds-flash`,
включая перезапуск сервера посреди задачи: ожидания ниже — то, что происходит на
самом деле, а не предположения.

---

## Часть 0. Подготовка

```bash
cd ~/Документы/AI-Advent-Challenge/Day-13
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
mv memory memory-до-проверки 2>/dev/null || true
python web.py
```

Откройте <http://127.0.0.1:5000>.

- [ ] Заголовок «Агент миграции ГИС — состояние задачи», под ним — вступление
      про три части состояния и паузу поверх этапа.
- [ ] В блоке «❓ Справка по форме» есть разделы «Состояние задачи» и «Пауза и
      продолжение».
- [ ] В «Модель» выбран **DeepSeek V4 Flash**.
- [ ] В «Режимах» появилась галочка **подтверждать смену стадии** — она нужна
      в части 5.

## Часть 1. Состояние задачи — три части, а не одна

**1.1.** В карточке «Задача»: поле «Новая» → `перенос-организаций`, «Название» →
`перенос справочника организаций`. Нажмите **Завести**.

- [ ] Под заголовком появилась карточка состояния из трёх строк:
      **этап** `planning (планирование)`, **шаг**, **ожидание**.
- [ ] Ожидание — `запустить` с пояснением «работа ещё не начиналась».
- [ ] Строка «шаг» говорит, что шагов нет: задача ведётся вручную.

Три части отвечают на три разных вопроса: на каком этапе работа, где именно мы
стоим и что должно произойти, чтобы задача сдвинулась. Одного этапа мало.

**1.2. План превращается в шаги.** Нажмите **Составить план**.

- [ ] В чате появился нумерованный план.
- [ ] В карточке состояния строка «шаг» стала вида «<первый пункт плана>
      (1 из N, план)», а под ней — лента шагов.
- [ ] Ожидание осталось `запустить`: план составлен, но работа по нему ещё не
      начиналась. На `продолжить` оно сменится, когда пойдёт первый шаг.

**1.3. Автомат не пускает мимо этапа.** Посмотрите на кнопки переходов.

- [ ] Из `planning` предложен только **→ execution**.
- [ ] Нажмите **Завершить и свернуть в решение** — в чате ошибка: из planning
      сразу в done нельзя.

Нажмите **→ execution**.

- [ ] Кнопок стало две: `validation` и `planning`, то есть возврат на доработку
      разрешён явно.

## Часть 2. Пауза по команде

**2.1.** Введите запрос, запускающий сценарий:

```
Напиши фичу: подсветка отключённых участков газопровода на карте
```

- [ ] В чате строка «Сработал сценарий…», шаги дорисовываются по одному.

**2.2.** Не дожидаясь конца, нажмите **Пауза**.

Если прогон успел остановиться сам с ожиданием `ответ-пользователя` — значит
сработала другая точка останова, из части 3: ответьте на вопрос, нажмите
«Ответить и продолжить» и нажмите «Пауза» на следующем шаге.

- [ ] В чате появилось системное сообщение вида «Пауза: этап планирование;
      шаг аналитик (1 из 5, сценарий); на паузе; ждём: можно продолжать».
- [ ] **Текущий шаг всё равно дописался до конца** — в списке шагов он
      отмечен готовым. Это нарочно: ответ модели уже оплачен.
- [ ] Карточка состояния подсветилась (жёлтая рамка) и показывает паузу.
- [ ] Причина в строке «этап» — «по команде», ожидание `продолжить`. Но если
      шаг, который дописывался, на выходе задал вопрос, причина сменится на
      «не хватает сведений», а ожидание — на `ответ-пользователя`: задача всё
      равно стоит, просто теперь видно, что именно нужно, чтобы она сдвинулась.
- [ ] Кнопка «Спросить» снова доступна: прогон действительно остановлен.

**2.3.** Нажмите **Продолжить**.

- [ ] В чате написано, с какого шага продолжаем: «Продолжаю задачу «…» с шага
      2 из 5. Пройденное не пересчитывается».
- [ ] Прогон пошёл дальше с **того же** шага, а не с начала: номера в чате
      сквозные по задаче, а не по заходу — после «1/5 · аналитик» идёт
      «2/5 · архитектор», и «ответ вам» стоит ровно у пятого шага.
- [ ] Пройденные шаги не переигрываются — новых вызовов по ним нет.

## Часть 3. Остановка за сведениями

Первому шагу каждого сценария разрешено остановиться и спросить, если данных не
хватает; остальным — нет (backend, получивший проект от архитектора, должен
писать код, а не переспрашивать).

**3.1.** Дождитесь конца прошлого прогона (или нажмите «Пауза»), затем запустите
сценарий на заведомо неполном запросе:

```
Напиши фичу: выгрузка участков во внешнюю систему
```

- [ ] Если аналитику не хватило данных, прогон встал: в состоянии ожидание
      `ответ-пользователя`, а в пояснении — сам вопрос и имя спросившего шага.
- [ ] В чате видно, на каком шаге остановились.

**3.2.** Впишите ответ в поле «Ответ на вопрос шага», например
`Выгружаем в 1С, формат JSON, раз в сутки`, и нажмите **Ответить и продолжить**.

- [ ] Прогон продолжился со следующего шага.
- [ ] Ответ попал в работу: в последующих шагах видно, что агент им
      воспользовался (упоминает 1С и JSON).

Если на вашем запросе аналитик ничего не спросил — это допустимо: право на
остановку есть, но пользуется им модель по обстоятельствам. Тогда проверьте
пункт 3 на другом неполном запросе или пропустите.

## Часть 4. Остановка перед сменой стадии

**4.1.** Поставьте галочку **подтверждать смену стадии** и запустите сценарий
заново на любом запросе с триггером.

- [ ] Прогон дошёл до шага, который требует другой стадии, и встал. (Если
      раньше сработала остановка за сведениями — ответьте на вопрос и
      продолжайте: подтверждение перехода придёт следующим.)
- [ ] Ожидание — `подтвердить-переход`, в пояснении названы обе стадии и шаг:
      «перейти со стадии «planning» на «execution» и запустить шаг «backend»?»
- [ ] Этап при этом **не сменился**: пауза — флаг поверх этапа, а не пятая
      стадия.

**4.2.** Нажмите **Продолжить**.

- [ ] Стадия сменилась, и шаг выполнился.
- [ ] Прогон **не** просит подтвердить тот же переход повторно. (Раньше здесь
      была ошибка: подтверждение снимало паузу, но переход не выполняло, и
      цикл просил подтвердить одно и то же бесконечно.)
- [ ] Следующая смена стадии снова требует подтверждения: согласие действует
      ровно на один переход.

Галочка должна оставаться включённой всё время прогона: страница присылает её
состояние с каждым запросом, и снятая посреди дела галочка означает «дальше без
подтверждений».

Снимите галочку.

---

## Часть 5. Продолжение переживает перезапуск

Это главная проверка дня: состояние задачи живёт на диске, а не в памяти
процесса.

**5.1.** Оставьте задачу на паузе (любым способом из частей 2-4). Запомните, на
каком шаге она стоит.

**5.2.** Остановите сервер (`Ctrl+C` в терминале) и запустите снова:

```bash
python web.py
```

**5.3.** Обновите страницу и выберите ту же задачу в списке «Задача».

- [ ] Карточка состояния показывает **тот же** этап, шаг и ожидание.
- [ ] Виден исходный запрос и результаты пройденных шагов.

**5.4.** Выберите в шапке модель заново (после перезагрузки там стоит «по
роли») и нажмите **Продолжить** — или, если задача ждёт ответа, впишите его и
нажмите **Ответить и продолжить**.

- [ ] Прогон идёт с того же шага: новый процесс ничего не переспрашивает и
      не переигрывает.
- [ ] Шаги продолжения идут на выбранной модели: в строках чата стоит
      `ds-flash`, а не модели из описания сценария.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «Сценарий уже идёт» | прогон не закончился: дождитесь или нажмите «Пауза» |
| «Пауза» ничего не меняет | флаг ставится перед следующим шагом — текущий всегда дописывается |
| после «Продолжить» шаги пошли заново | значит, выбрана другая задача: проверьте список «Задача» |
| прогон встал с «решение-человека» | ответ шага не уложился в ограничения проекта — это четвёртая точка останова |
| ответы идут медленно | выбрана бесплатная модель и упёрлись в минутный лимит — переключитесь на `ds-flash` |

После проверки можно вернуть прежнюю память:

```bash
rm -rf memory && mv memory-до-проверки memory
```
