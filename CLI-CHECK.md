# Проверка Дня 13 через консоль

То же, что `MANUAL-CHECK.md`, но без браузера: состояние задачи, пауза и
продолжение проверяются командами `cli.py`. У консоли здесь важное
преимущество — **каждая команда это отдельный процесс**, поэтому «продолжение
переживает перезапуск» проверяется само собой, без остановки сервера.

Все команды идут с `--память-в cli-check-memory`, чтобы не трогать рабочую память
проекта, и с `--модель ds-flash` — она платная, но быстрая и не упирается в
минутные лимиты Groq.

Прогон целиком автоматизирован: `python check_cli.py` выполняет все шаги ниже на
живой модели и пишет отчёт в `CLI-CHECK-RESULTS.md`.

```bash
cd ~/Документы/AI-Advent-Challenge/Day-13
source .venv/bin/activate        # иначе везде python3 вместо python
python check_cli.py              # весь прогон + отчёт
python check_cli.py --в отчёт.md # положить отчёт в другой файл
python check_cli.py --без-сценария   # быстро: без пятишагового прогона
```

Ниже — то же самое руками, по шагам.

## Часть 1. Три части состояния

**1.1. Завести задачу**

```bash
python cli.py --память-в cli-check-memory --новая-задача перенос-организаций \
              --название "перенос справочника организаций"
```

- [ ] Ответ: «Задача «перенос-организаций» заведена, стадия planning».

**1.2. Посмотреть состояние**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --состояние
```

- [ ] Печатаются три части: `этап planning (планирование), идёт`,
      `шаг шагов нет — задача ведётся вручную`,
      `ожидание запустить — работа ещё не начиналась`.
- [ ] Строкой ниже — куда можно перейти: «дальше можно: execution».

**1.3. Прыжок через этап отклоняется**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --завершить
```

- [ ] Ошибка: «Из стадии «planning» нельзя сразу в done. Разрешено: execution».
- [ ] Код возврата ненулевой — скрипт, который на это наткнётся, узнает о сбое.

**1.4. План превращается в шаги** (живой вызов модели)

```bash
python cli.py --память-в cli-check-memory --модель ds-flash \
              --задача перенос-организаций --план
```

- [ ] Печатается нумерованный план.
- [ ] Ниже: «В рабочую память записано шагов: N».

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --состояние
```

- [ ] Теперь `шаг` — первый пункт плана с пометкой «(1 из N, план)».
- [ ] `ожидание` по-прежнему `запустить`: план есть, работа не начиналась.
- [ ] Ниже перечислены сами шаги со значком состояния (пусто / `>` / `+`).

**1.5. Разрешённые переходы**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия execution
```

- [ ] «Стадия: execution. Дальше можно: validation, planning».

## Часть 2. Пауза на задаче, которую ведут руками

**2.1. Остановить**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --пауза
```

- [ ] «Задача «перенос-организаций» остановлена» и одной строкой её состояние.
- [ ] Подсказка: «Текущий шаг доведён до конца… Продолжить: --продолжить».

**2.2. Пауза видна другому процессу**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --состояние
```

- [ ] В строке `этап` написано `НА ПАУЗЕ`, ниже — «причина остановки: по команде».
- [ ] Этап при этом прежний (`execution`): пауза — флаг поверх этапа, а не
      пятая стадия.

**2.3. Продолжать нечего**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --продолжить
```

- [ ] Отказ: «Задача … велась не по сценарию — продолжать нечего». Ручную
      задачу двигает человек, а `--продолжить` предназначен для сценариев.

## Часть 3. Сценарий с подтверждением перехода

**3.1. Запустить по шагам**

```bash
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --сценарий "напиши фичу" "Напиши фичу: слой колодцев на карте"
```

- [ ] Шаги печатаются по мере готовности: «1/5 · аналитик · planning · ds-flash».
- [ ] Прогон **останавливается** и печатает, на чём именно: либо
      «ожидание: подтвердить-переход» с вопросом «перейти со стадии … и
      запустить шаг …?», либо «ожидание: ответ-пользователя», если первый шаг
      попросил сведений.
- [ ] В конце — готовая команда продолжения, и ключ в ней зависит от ожидания:
      `--ответ «текст»`, если шаг задал вопрос, и `--продолжить`, если ждут
      подтверждения перехода. Там же сказано, что состояние лежит на диске и
      продолжить можно из другого запуска.

**3.2. Задача видна в списке**

```bash
python cli.py --память-в cli-check-memory --задачи
```

- [ ] В списке есть задача сценария с пометкой «на паузе» и номером шага.

**3.3. Состояние из нового процесса**

```bash
python cli.py --память-в cli-check-memory --задача <ид-задачи> --состояние
```

- [ ] Этап, шаг и ожидание те же, что напечатал прогон: состояние прочитано с
      диска, а не из памяти прежнего процесса.
- [ ] Видны пройденные шаги с плюсами и их выжимки.

## Часть 4. Продолжение в новом процессе

**4.1. Ответить или подтвердить**

```bash
# если ждут ответа:
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --задача <ид> --ответ "Колодцы лежат в gisdata, SRID 3857"
# если ждут подтверждения перехода:
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --задача <ид> --продолжить
```

- [ ] Прогон идёт **с того же шага**: номера продолжают ряд, пройденное не
      переигрывается.
- [ ] Каждый шаг идёт на `ds-flash` — выбранная модель сильнее ролей шагов.
- [ ] Если включён `--по-шагам`, прогон снова встанет на следующей смене
      стадии: согласие действует ровно на один переход.

**4.2. Довести до конца**

Повторяйте `--продолжить` (или `--ответ`), пока прогон не закончится.

- [ ] В конце: «Сценарий отработал» и итог последнего шага.
- [ ] Задача свёрнута в журнал решений, и `--задачи` её больше не показывает.

## Часть 6. Диалоговый режим

```bash
printf 'состояние\nпомощь\nвыход\n' | \
  python cli.py --память-в cli-check-memory --задача перенос-организаций
```

- [ ] Команда `состояние` печатает ту же карточку, что ключ `--состояние`.
      Задачу нужно указать ключом: без `--задача` диалог начинается без активной
      задачи и честно отвечает «Активной задачи нет».
- [ ] `помощь` перечисляет команды диалога, среди них `пауза`, `продолжить`,
      `ответ текст`, `состояние`.
- [ ] `выход` завершает работу без ошибок.
